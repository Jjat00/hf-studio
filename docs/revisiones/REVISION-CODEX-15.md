## Hallazgos

1. **[P1] `connect --print` puede desconectar un agente ya registrado, aunque promete solo imprimir.** `src/hf_studio/cli.py:129-141` omite `already_registered` cuando `--print` está presente, pero siempre llama a `issue_key`. Esta función rota inmediatamente la clave del cliente existente (`src/hf_studio/setup.py:69-79`) antes de imprimir el comando. Si Codex o Claude Code ya usa esa clave, una consulta inocente a `connect codex --print` lo deja con un token revocado. El mismo riesgo existe con `claude-desktop` y `json`, cuyos registros externos ni siquiera se pueden detectar. `README.md:124-125`, `README.es.md:136-137` y la ayuda de CLI describen `--print` como una operación que solo muestra la configuración. Separar una vista sin mutación de la emisión o rotación explícita de claves, y probar una segunda ejecución con un cliente registrado.

2. **[P1] El primer arranque crea los archivos con secretos legibles para otros usuarios locales con el `umask` habitual.** `ensure_env` copia `.env.example` mediante `shutil.copyfile` y `ensure_ui_key` hace lo mismo con `web/.env.example` (`src/hf_studio/setup.py:44-45,90-94`); `set_env` conserva los permisos del archivo (`:33-39`). Con `umask 022`, ambos archivos nuevos quedan en modo `0644`. El primero contiene las claves de Higgsfield y ElevenLabs; el segundo contiene una clave `hfs_…` capaz de generar y, por defecto, ver y gestionar los trabajos de todos. `.gitignore` impide publicarlos en Git, pero no limita su lectura local. Crear ambos con modo `0600` y verificarlo en tests, sin relajar permisos de archivos existentes.

3. **[P2] Un `web/.env.local` antiguo puede pasar la comprobación aunque no sea la identidad o la URL de esta UI.** `ensure_ui_key` acepta cualquier token válido de `api_clients` sin comprobar `name == "web-ui"` ni `sees_all` (`src/hf_studio/setup.py:83-89`). Si se reutilizó una clave de otro cliente, la UI operará como ese cliente; si la clave `web-ui` perdió `see-all`, la biblioteca ya no mostrará los trabajos de los agentes. Además, conserva cualquier `HF_STUDIO_URL` no vacío (`:93`), aunque `dev.sh` siempre inicia la API en `127.0.0.1:8787` (`dev.sh:22`): una URL vieja apunta la UI a otra API. Los tests solo cubren una creación nueva y una segunda ejecución con estado sano (`tests/test_setup.py:56-61`). Validar identidad, alcance y URL para el flujo local, y probar configuraciones antiguas.

4. **[P2] `setup` usa dos nociones distintas de ubicación y de configuración.** `ensure_env` solo busca la clave en el `.env` junto al código (`src/hf_studio/setup.py:17-20,42-50`), mientras `get_settings()` lee `.env` desde el directorio de ejecución y también acepta variables de entorno (`src/hf_studio/config.py:8-15,64-66`). Si una automatización suministra `HF_API_KEY` por entorno y ejecuta `setup --no-input`, el comando falla pese a tener la clave. Si se ejecuta `hf-studio setup` o `connect` desde otro directorio, `_check_credentials` y `_with_session` usan esa otra configuración y su base SQLite relativa (`src/hf_studio/cli.py:15-20,113-125`), mientras el MCP registrado arranca en `ROOT` mediante `uv run --directory` (`src/hf_studio/setup.py:99-100`). La clave creada puede quedar en otra base y fallar la autenticación del MCP. `./dev.sh` evita el caso cambiando primero al repo; los comandos CLI publicados no lo garantizan. Unificar la ruta base o documentar y hacer cumplir el directorio de trabajo.

5. **[P2] Un fallo al registrar el MCP puede invalidar una clave y aun así terminar con código de éxito.** `already_registered` trata cualquier salida distinta de cero de `mcp get` como «no registrado» (`src/hf_studio/setup.py:106-112`), incluso un fallo del CLI. Después `issue_key` rota la clave antes de ejecutar `mcp add` (`src/hf_studio/cli.py:129-141`). Si `mcp add` falla, `connect` imprime un comando manual y devuelve `0` (`src/hf_studio/setup.py:135-145`); en una instalación existente, la configuración conserva la clave vieja y queda rota. Distinguir «no existe» de error de consulta, no rotar antes de asegurar el registro nuevo, y devolver fallo si el registro solicitado no ocurrió. `AGENTS.md:19-20` y ambos README prometen que el comando registra el servidor.

6. **[P2] El comando impreso no cita rutas de forma segura para una shell.** `_quote` usa `json.dumps` cuando hay espacios u otros caracteres (`src/hf_studio/setup.py:143-149`). Una ruta como `/tmp/a space/$HOME` se imprime con comillas dobles, por lo que la shell expande `$HOME`; una con `$(...)` ejecuta sustitución de comandos si el usuario la pega. Los argumentos pasados directamente a `subprocess.run` sí conservan la ruta. Usar comillas POSIX adecuadas para la salida de shell y probar espacios, `$`, acentos y comillas. El JSON para Claude Desktop es una configuración JSON, no tiene este problema.

7. **[P2] La clave opcional de ElevenLabs deja de ofrecerse si Higgsfield ya estaba configurado.** `ensure_env` pide ambas claves dentro de `if not has_hf and interactive` (`src/hf_studio/setup.py:47-66`). Si alguien preparó `.env` con `HF_API_KEY`, o ejecutó primero `./dev.sh api` sin ElevenLabs y luego quiere activar audio, otra ejecución de `./dev.sh` no le pide esa clave. La frase «la primera vez pide tu clave de Higgsfield (y, opcionalmente, la de ElevenLabs)» de ambos README solo se cumple cuando faltaba Higgsfield. Preguntar por ElevenLabs cuando esté ausente en una terminal, sin sobrescribir una clave ya guardada, o explicar expresamente cómo añadirla después.
